# 网关管理面板

`gateway` 子命令可以托管 core 的 ToolRegistry 管理面板，并加载网关管理扩展，从而提供
六个运维页面：

| 页面 | 管理内容 |
|------|----------|
| **Keys（密钥）** | OpenAPI 与 MCP 前端接受的入站客户端密钥 |
| **Clients（客户端）** | 每个客户端的实时调用计数 |
| **Frontends（前端）** | 每个网关前端的启用标记与挂载路径 |
| **Sources（来源）** | 在运行期添加、编辑、测试或移除的工具来源 |
| **Tools（工具）** | 单个工具的 schema 与受保护的调用测试器 |
| **Logs（日志）** | 按 principal、结果、工具与时间筛选的执行日志 |

该面板是运维面。它使用 core 面板自己的令牌与会话鉴权，刻意不属于保护工具前端的
`--tokens` 集合。客户端密钥无法访问这些页面中的任何内容。

## 启用面板

管理前端默认禁用。用 `--admin` 启用，并用 `--admin-token` 或更推荐的
`--admin-token-file` 提供运维令牌，避免密钥出现在进程列表中：

```bash
toolregistry-server gateway \
  --config tools.yaml \
  --keys-db keys.db \
  --admin \
  --admin-token-file operator-token.txt
```

- 启用前端但未配置运维令牌会导致启动失败。
- 网关的对外令牌无法打开面板：只携带 `--tokens` 凭据的请求会得到 `401`。
- 挂载路径默认为 `/admin`；用 `--admin-path` 或
  `gateway.frontends.admin.path` 修改。
- 托管面板要求 core `toolregistry` 提供管理扩展契约（`ADMIN_EXTENSION_API == 1`，
  即 core 0.21.0 或更新版本）。旧版 core 上该前端会以明确错误拒绝启动；默认配置
  不会加载它。

启用后，面板外壳位于挂载路径（默认 `http://host:8000/admin/`），网关页面位于其下：
`/admin/ext/gateway/keys`、`/admin/ext/gateway/clients`、
`/admin/ext/gateway/frontends`、`/admin/ext/gateway/sources`、
`/admin/ext/gateway/tools` 与 `/admin/ext/gateway/logs`。在控制台导航中该扩展是一个
名为 **Gateway** 的标签页，默认打开 **Keys**。

禁用管理前端后，面板根路径及其下所有扩展页面在下一个请求返回 `404`，无需重启。

## Keys 页面

Keys 页面管理 OpenAPI 与 MCP 前端接受的限定作用域入站密钥。它使用 `--keys-db`
指定的存储；未配置该选项时页面返回 `503`，工具前端只保留静态 `--tokens` 凭据。
面板与工具前端共享同一个数据库，因此在这里创建的密钥在下一个请求即被前端接受，
撤销的密钥在下一个请求即被拒绝。

表格每行一个密钥：

| 列 | 含义 |
|----|------|
| 名称（Label） | 面向运维的名称 |
| 权限范围（Scopes） | 命名空间，以及按工具的允许/拒绝覆盖 |
| 调用（Calls） | 记录到该密钥的调用次数 |
| 成功（OK） | 处理器正常返回的调用 |
| 错误（Errors） | 处理器抛出异常的调用 |
| 繁忙（Busy） | 被客户端并发上限拒绝的调用 |
| 拒绝（Denied） | 被密钥作用域或权限策略拒绝的调用 |
| 最近成功（Last success） | 最近一次成功调用的时间，或 `—` |
| 状态（Status） | `有效`、`已过期` 或 `已撤销` |
| 操作（Actions） | 按密钥状态提供 `详情`、`编辑`、`轮换` 与 `撤销` |

已撤销与已过期的密钥仍保留在表格中，便于查看历史。存储只保留密钥的哈希；任何响应
与静态资源都不包含明文密钥。

### 用量计数

用量列读取的是持久化在密钥数据库中的计数，而不是执行日志。每个计入某个密钥的
调用或拒绝都会递增它所在的行，因此重启后计数仍在，密钥被撤销或过期后也仍然可见。
Keys 页面在列出密钥时用一次查询读取全部计数。

!!! note "用量与 Logs 页面"
    执行日志是每进程 1000 条的内存环。密钥计数是累计的、没有上限，因此超出该
    窗口后两个视图按设计就会不同：Keys 页面继续累加，而 Logs 页面已经丢弃了最早
    的条目。只有在日志当前窗口内比较某个密钥的计数与 Logs 页面才有意义。网关自己的
    Logs 标签页读取同一个内存环，并按 principal、结果、工具与时间筛选。

没有记录的密钥显示全零。用量响应从不包含密钥值。

### 创建密钥

填写表格下方的表单：

- **名称（Label）** — 必填；仅用于显示，不要求唯一。
- **权限范围（Scopes）** — 以逗号分隔的命名空间列表。`*` 匹配所有命名空间，
  `web/*` 匹配 `web` 及其下的任意命名空间。
- **按工具覆盖（Tool overrides）** — 每行一个 `tool=allow` 或 `tool=deny`，例如
  `web-dangerous=deny`。覆盖始终优先于命名空间列表，因此在允许的命名空间中拒绝
  某个工具、或在命名空间之外允许某个工具，都通过它表达。
- **过期时间（Expires）** — 可选的本地时间。网关会把它转换为绝对时间戳发送，存储会
  拒绝过去的时间。
- **并发（Concurrency）** — 可选；该密钥同时可运行的最多调用数。它只能调低服务器的
  `--client-concurrency`，不能调高；留空表示使用服务器默认值。

空的命名空间列表且没有覆盖，会创建一个什么都调用不了的密钥；这是失败即关闭的默认。

创建成功后，页面只显示一次密钥，并提供复制按钮：

!!! warning "密钥只显示一次"
    完整密钥只出现在创建响应中，该响应带有 `Cache-Control: no-store`。页面不会
    保存它，事后也无法找回。若关闭对话框时没有复制，只能重新创建一个密钥。

### 轮换密钥

**轮换（Rotate）** 会先请求确认，然后为该密钥签发新的密钥值。密钥 id、名称、
作用域、过期时间、并发上限与用量历史都保持不变，只有密钥值改变；旧密钥值在下一个
请求时被拒绝。

新密钥值与创建密钥时一样，在同一个一次性面板中只显示一次，响应带有
`Cache-Control: no-store`。事后无法找回，只能再次轮换取得新的密钥值。

**轮换** 只对 `有效` 的密钥提供。已撤销的密钥不能轮换；已过期的密钥需要先用
**编辑** 延长或清除过期时间。

### 编辑密钥

**编辑（Edit）** 打开一个表单，包含名称、权限范围、按工具覆盖、并发与过期时间，
并填入密钥的当前值。**保存（Save）** 只发送这些字段，修改在下一个请求生效，
无需重启。

- **名称** 必填且不能为空。
- **权限范围** 是以逗号分隔的命名空间列表；**按工具覆盖** 每行一个
  `tool=allow` 或 `tool=deny`。
- **过期时间** 留空表示不过期。过去的时间会被拒绝。
- **并发** 留空表示使用服务器默认值。

未做任何修改就保存会被拒绝，并提示「请至少修改一个字段。」

已撤销的密钥不提供 **编辑**。已撤销的密钥保留历史，但不能再修改。

### 密钥详情

**详情（Details）** 打开单个密钥的只读视图：名称、id、权限范围、按工具覆盖、
创建时间、过期时间、最近使用、并发、状态，以及包括最近成功在内的全部用量计数。
它通过 `GET /ext/gateway/keys/<key_id>` 从存储读取密钥，因此显示的是当前行，
而不是最近一次列表刷新的快照。

### 撤销密钥

**撤销（Revoke）** 会先请求确认，然后立即把密钥标记为已撤销。使用该密钥的客户端在
下一次请求时被拒绝。撤销是幂等的，并保留最初的撤销时间。已撤销的密钥保留其行与
用量计数。

### 限定作用域的密钥与延迟工具

!!! note "限定作用域的密钥与发现代理"
    限定作用域的密钥保留 `discover_tools` 与 `call_deferred`，两者都会对它们所操作
    的工具执行该密钥的作用域：发现只返回密钥可调用的名称，`call_deferred` 命中
    作用域外目标时的拒绝信息与直接调用完全一致。无论密钥的命名空间是什么，这对代理
    都可见——它们位于 default 命名空间——但针对任一名称的显式单工具拒绝仍会将其
    移除。运维身份与静态令牌不受影响。见[认证](authentication.md)。

## Frontends 页面

Frontends 页面列出每个网关前端 —— `openapi`、`mcp`、`sse` 与 `admin` ——
以及其路径、传输与启用标记，并修改与 `gateway.list_frontends()`、
`gateway.update_frontend()` 相同的注册表。

- **启用/禁用** 在下一个请求生效。被禁用的前端在其应用或注册表运行之前返回 `404`，
  其他前端继续服务。切换不会重建 MCP 会话管理器。
- **路径** 必须以 `/` 开头，必须唯一，且不能包含空白、`?`、`#` 或 `//`。新路径在
  下一个请求生效。
- **持久化**：变更在复制 `<config>.bak` 之后写回配置文件。结果行会说明是否已持久化；
  未持久化时页面显示原因，而不是假装成功。仅运行期部署（没有配置文件路径，或使用
  `--no-config-write`）只在内存中保留变更，直到进程退出。
- **注释丢失**：重写 JSONC 配置会丢失其中的注释。更新响应会带上警告，页面会显示它；
  若注释重要，请改用 YAML 配置或保留副本。
- **后端限制**：多个前端必须使用 `fastapi` 后端。`--backend httpserver` 只能在
  监听器根路径提供 openapi 前端，因此启用了管理前端的网关不能使用该后端，openapi
  路径覆盖也会被拒绝而不是被忽略。

允许在该页面禁用 `admin` 前端；此后面板返回 `404`，页面本身在通过配置文件或进程
参数重新启用之前不可达。

## Sources 页面

Sources 页面显示运行期来源管理器的视图：每行一个已声明的来源，包含类型、详情、
命名空间、已启用/工具总数、状态与最近错误。

| 状态 | 含义 |
|------|------|
| `已应用`（Applied） | 来源已注册其工具 |
| `已排除`（Excluded） | 部署配置把该来源过滤掉了；进入适用范围后会注册 |
| `失败`（Failed） | 最近一次应用失败；错误已脱敏并显示在该行 |

操作：

- **添加来源（Add source）** — 选择类型（`OpenAPI`、`MCP`、`Python`），填写规范或
  服务地址，Python 来源填写模块/类，并可选填命名空间。MCP 来源还要选择传输方式
  （`streamable-http`、`sse` 或 `stdio`），HTTP 传输可附带凭据。网关校验声明，并
  转换为与配置文件相同的类型化来源对象，应用部署配置，并通过来源管理器持久化这次
  添加。
- **编辑（Edit）** — 打开同一个表单，并通过
  `GET /ext/gateway/sources/<id>` 用已保存的声明预填；保存走
  `PUT /ext/gateway/sources/<id>`。保存以一次差异替换声明：注销旧工具并注册新集合。
  表单不显示的字段——`tags`、`include`、`exclude`，以及 MCP 的 `persistent` 或
  OpenAPI 的 `base_url`——会从已保存的声明中原样带入，因此修改无关字段不会重置它们。
- **测试（Test）** — 在不注册任何内容的前提下检查声明。
  `POST /ext/gateway/sources/test` 测试表单当前内容；
  `POST /ext/gateway/sources/<id>/test` 测试已保存的来源。MCP 来源会打开一次性会话，
  执行 `initialize` 与 `tools/list`，报告工具数量以及服务器名称与版本。OpenAPI 来源
  会拉取并解析文档，统计其中的操作数。失败时原样返回错误及其异常类型，URL 中的凭据
  会被脱敏。
- **工具（Tools）** — 展开该行并列出来源已注册的工具，包含名称、简短描述与启用状态
  （`GET /ext/gateway/sources/<id>/tools`）。注册表中已不存在的名称不会被报告为
  启用。
- **重试（Retry）** — 只对 `失败` 的来源显示。它会重新应用未改变的声明；部分注册会
  回滚，因此重试不会重复注册工具。非失败的来源保持不变。
- **移除（Remove）** — 注销该来源的工具并持久化移除。

### 凭据只写不读

声明可能携带凭据：MCP 的 `headers`、Python 来源的构造参数 `kwargs`，以及 OpenAPI 的
`auth.token`。任何 GET 响应都不会包含它们的值。`GET /ext/gateway/sources/<id>` 返回的
声明已去掉这些字段，并在 `secret_fields` 中列出它们的名称，例如
`["headers.Authorization"]`，因此表单可以提示已保存凭据并再次索取。写在 `url` 或
`base_url` 里的凭据（`user:password@` 部分）同样会被脱敏，字段名本身列入
`secret_fields`。表单原样提交回来的 URL，或根本没有提交的 URL，都会保留已保存的值
（含 userinfo）。

有一个字段有意不当作密钥处理：MCP stdio 来源的 `command` 会原样返回，因为它是编辑该
声明的唯一途径。凭据应放在 `env` 中，其值会被隐藏。

由于表单从未收到该值，保存时凭据字段留空会保留已保存的值。要删除凭据，请勾选
**删除已保存的凭据**，它会发送 `clear_secrets: true`，删除已保存的 `headers`、`env`、
`kwargs` 与 `auth.token`，而不是与它们合并。同时携带 `auth` 与 `clear_secrets` 的请求
会被拒绝。

对 MCP 来源，表单中的凭据按配置文件的方式保存为请求头：Bearer 令牌写成
`Authorization: Bearer <token>`，自定义请求头则把令牌存在给定的头名称下。若 `headers`
中已设置同名请求头，请求会被拒绝，因此凭据只有一个存放位置。

配置文件无法写入时，变更仍在内存中生效，页面显示未保存及其原因。只读配置不会被
报告为成功。

面板自身的 **Sources** 标签页（core 面板的部分，不属于 Gateway 页面）仍提供
预览 → 勾选工具 → 注册的流程。预览不会注册任何内容，只列出来源提供的工具；注册只
发送勾选的名称，并通过同一钩子持久化。若想在添加来源前查看工具列表，使用它；
Gateway 的 Sources 页面适合已明确知道内容的来源。

## Tools 页面

Tools 页面列出每个已注册的工具（包括已禁用的），包含命名空间、来源、启用状态与标签
（`GET /ext/gateway/tools`）。**查看（Inspect）** 打开单个工具的详情
（`GET /ext/gateway/tools/<name>`）：完整描述、客户端实际收到的输入 schema、输出
schema、标签、命名空间、启用状态与禁用原因、来源及其脱敏后的详情，以及执行提示。带有
`destructive` 或 `privileged` 标签的工具在调用前会被明确提示。

详情视图同时承载调用测试器。它不是第二条执行路径：调用会走与客户端调用相同的步骤——
共享的参数校验器按对外发布的 schema 校验、进程权限策略、路由处理器，以及以运维
principal 记录的带归属执行日志。

- 参数框以输入 schema 生成的骨架为起点，以 JSON 发送。
- 每次调用都必须勾选 **我了解此调用会在服务器上执行**，它发送 `confirm: true`；
  否则路由返回 `409`。
- 已禁用的工具在执行前以 `409` 拒绝，详情视图会禁用表单。请先启用该工具。
- 参数不合法时返回 `400` 并附带校验器的详情；权限策略拒绝时返回 `403`。
- 处理器失败时以 `ok: false` 返回原样错误及其异常类型，并按对应结果写入日志。
- 被拒绝的调用——已禁用、未确认或被策略拒绝——以 `denied` 结果记入运维 principal 名下的
  日志，因此在 Logs 页面筛选中与客户端被策略拒绝的调用一样可见。参数不合法导致的拒绝
  只返回给页面而不写日志，因为没有真正发起调用。
- 调用成功时显示编码后的结果与毫秒级耗时。

测试器属于运维面：没有面板的运维会话时所有路由都返回 `401`，页面上也无法调用任何
工具。

## Logs 页面

Logs 标签页读取注册表执行日志，并按 principal、结果、工具与时间范围筛选
（`GET /ext/gateway/logs`）。同一组筛选条件也用于 `GET /ext/gateway/logs/stats`，
因此计数始终描述表格展示的那些行。

| 筛选 | 取值 |
|------|------|
| Key id | 已保存的密钥 id。`operator` 只选出归属运维 principal 的条目，绝不包含匿名条目 |
| Key label | 记录下来的 principal 名称，大小写不敏感 |
| 结果（Outcome） | `ok`、`error`、`busy`、`denied`、`timeout` 或 `disabled` |
| 工具（Tool） | 精确的工具名 |
| 起始 / 结束（Since / Until） | 条目时间的闭区间 ISO 8601 边界 |
| 条数（Limit） | 返回的行数，1 到 1000（默认 100） |

所有筛选条件可以组合，结果按时间倒序返回。结果筛选优先读取条目记录的结果
（`metadata.outcome`），缺失时回退到条目状态，因此只要后端记录了，`busy` 与 `denied`
行就能被筛出：MCP 的拒绝，以及 OpenAPI 的作用域、代理目标或策略拒绝都记为 `denied`，
而没有获得并发槽位的调用记为 `busy`。

每行显示时间、工具、principal、密钥 id、状态与耗时。principal 列是记录下来的客户端
身份：API 密钥显示其密钥名称，OAuth principal 显示其 OAuth 客户端 id，从 Tools 测试器
发起的调用显示 `operator`，没有任何归属的调用显示 `anonymous`。统计区报告条目数、
平均耗时，以及按状态、工具与 principal 的分布。

!!! note "扩展的 Logs 标签页与 core 的 Logs 页面"
    core 面板自己的 Logs 页面由已安装的 `toolregistry` 包在 `/api/logs` 提供，只有
    工具、状态与警告筛选。网关无法给自己不拥有的处理器增加查询参数，因此筛选视图
    由 `/ext/gateway/logs` 提供，并渲染在扩展自己的标签页中。该标签页补充而不是
    取代 core 页面；两者读取同一个内存日志。

## 安全说明

- 面板及其扩展页面仅供运维使用。客户端密钥不会授予访问权限，扩展也不添加自己的
  任何鉴权代码：它继承面板的会话与面板的跨站防护。
- 扩展资源是通过面板资源处理器提供的静态 JavaScript 与 CSS。任何资源都不包含密钥，
  页面只在内存中保留一次性密钥。
- 面板会在页面处理器运行之前检查每个请求路径；扩展下的未知路径返回面板的 JSON
  错误结构。
- 来源凭据只写不读。GET 响应只列出已保存的凭据字段名，从不返回值；URL userinfo 中的
  凭据会被脱敏。保存时字段留空会保留已保存的值，删除必须显式操作。
- 调用测试器走客户端的执行路径，因此无法绕过参数校验器、进程权限策略或执行日志。
  它需要运维会话，并且每次调用都要显式确认。
